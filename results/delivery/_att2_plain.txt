   1| 模拟器通信接口说明及编程指南
   2| 1. 基本设定
   3| 1.1. 目标区域与坐标系
   4| 测试在一个二维虚拟目标区域中进行。
   5| 目标区域是半径 1800 米的圆形区域。
   6| 所有干扰源位于目标区域内。
   7| 目标区域圆心是坐标原点 (0,0)。
   8| x 轴正方向为东。
   9| y 轴正方向为北。
  10| 坐标单位为米。
  11| 机器狗可以向模拟器提交目标区域外的位置；模拟器仍会按提交的位置计算移动耗时和检测、清除结果。
  12| 机器狗位置不构成正常策略约束，但每个坐标分量必须是有限数值，且绝对值不得超过2000000米。NaN、正负无穷大和超出范围的坐标返回HTTP 400，请求不执行，也不推进位置或虚拟时间。
  13| 1.2. 角度约定
  14| 所有方位角都采用以下约定：
  15| 正东方向为 0∘。
  16| 逆时针方向为正。
  17| 正北方向为 90∘。
  18| 正西方向为 180∘。
  19| 正南方向为 270∘。
  20| 角度范围为 [0,360)。
  21| /measure 返回的 svd_deg 表示干扰源的示向度，单位为度。
  22| 1.3. 频道
  23| 频道用整数表示。
  24| 有效频道范围是 {1,2,⋯,20}。
  25| 每个频道最多对应一个干扰源。
  26| 一次测试中干扰源总数量在 10 到 16 个之间。
  27| 具体有多少个干扰源不会通过接口直接返回，机器狗程序需要根据检测和清除结果自行判断。
  28| /measure 的 channel 表示测向机要检测的频道。
  29| /clear 的 channel 表示要尝试清除的目标干扰源频道。
  30| 注意：/clear 的 channel 不会改变测向机当前频道，也不会产生切换频道耗时。
  31| 1.4. 初始状态
  32| 机器狗成功调用 /enter 后，模拟器初始状态如下，并开始计时：
  33| 初始位置：(0,0)。
  34| 测向机初始频道：1。
  35| /enter 本身不推进虚拟时钟。
  36| 每次测试只允许一个与当前登录参赛队号一致的机器狗进入。机器狗必须逐次发送动作，并在收到本次完整HTTP响应后再发送下一个新动作。正常串行合法请求没有请求速率上限；每次检测的5秒只增加虚拟时间，不要求在现实中等待5秒。
  37| 1.5. 其他信息
  38| 模拟器默认服务地址：http://127.0.0.1:2026。
  39| 选手可以在模拟器空闲时修改端口。
  40| 模拟器只监听本机回环地址，其他电脑不能直接访问该接口。
  41| 非测试期间、5秒倒计时期间以及测试结束后，机器狗接口未开放，连接可能直接失败。
  42| 2. 关键物理规则
  43| 2.1. 最大可被有效接收距离
  44| 每个干扰源都有一个最大可被有效接收距离，简称有效接收半径。
  45| 该距离在 1000 米到 1500 米之间。
  46| 距离超过该干扰源的有效接收半径时，机器狗在该位置接收不到该频道信号。
  47| 该距离不是固定常数，不同干扰源可能不同。
  48| 模拟器接口不会返回某个干扰源的有效接收半径。
  49| 2.2. 全向与定向干扰源
  50| 干扰源分为全向和定向两类。
  51| 全向干扰源：检测点到干扰源的距离不超过有效接收半径时，可以检测到信号。
  52| 定向干扰源：检测点必须同时满足距离条件，并且位于该干扰源的有效覆盖角度范围内，才能检测到信号。有效覆盖角度范围为 180∘（包含边界），定向方向未知。
  53| 因此，/measure 返回无信号时，只能说明当前位置接收不到该频道信号。可能原因包括：
  54| 该频道没有未清除干扰源。
  55| 距离超过有效接收半径。
  56| 该频道干扰源是定向干扰源，但当前位置不在它的覆盖范围内。
  57| 2.3. 示向度误差
  58| /measure 返回的 svd_deg 是示向度，不是干扰源的精确真实方位。
  59| svd_deg 表示在检测点处测得的干扰源的示向度，单位为度。
  60| 模拟器返回的 svd_deg 与干扰源的最大场强方向的真实方位角之间存在一定的误差，参见题目正文。
  61| 误差范围为 [-1∘, 1∘]。
  62| 返回值保留两位小数。
  63| 返回值仍按 [0,360) 归一化。
  64| 机器狗程序不应把单次 svd_deg 当作完全精确的真实方位。
  65| 2.4. 近距离阈值与清除半径
  66| 近距离阈值为 5 米。检测距离不超过 5 米并且位于干扰源信号覆盖角度范围内时，由于信号太强，将无法获得示向度信息，/measure 返回 measure_result="near"，不返回 svd_deg。
  67| 清除半径为 20 米。清除位置与目标干扰源距离小于等于 20 米时，/clear 可以清除成功。注：光学精确定位及清除操作是否成功仅与清除点与干扰源之间的距离有关，与定向干扰源的朝向无关。
  68| 3. 指令
  69| 机器狗程序只需要调用 4 条 HTTP 接口：
  70| 指令
  71| 含义
  72| 是否推进虚拟时钟
  73| POST /enter
  74| 进入目标区域，开始本次运行。
  75| 否
  76| POST /measure
  77| 到指定位置，对指定频道检测。
  78| 是
  79| POST /clear
  80| 到指定位置，尝试清除指定频道的干扰源。
  81| 是
  82| POST /exit
  83| 退出目标区域，结束本次运行。
  84| 否
  85| 移动和切换频道没有单独的接口：
  86| 移动由 /measure 或 /clear 请求中的 position 体现。
  87| 切换测向机频道只由 /measure 请求中的 channel 体现。
  88| 4. 虚拟时间计算方法
  89| 4.1.虚拟时钟推进规则
  90| 只有请求被模拟器接受，即响应中 accepted=true 时，才可能推进虚拟时钟。
  91| /enter：accepted=true 时也不推进虚拟时钟。
  92| /exit：accepted=true 时也不推进虚拟时钟。
  93| /measure：accepted=true 时推进虚拟时钟。
  94| /clear：accepted=true 时推进虚拟时钟。
  95| accepted=false：本次请求不生效，虚拟时钟不推进。
  96| accepted=false 的响应里 virtual_time_s 为 0。不要把这个 0 当作当前虚拟时刻。需要记录虚拟时刻时，应使用最近一次 accepted=true 的响应。
  97| virtual_time_s 是JSON number，可能带小数，不应按整数解析。模拟器内部按微秒累计，响应最多保留6位小数，并删除无意义的末尾零。
  98| 4.2. 移动耗时
  99| 模拟器会记录机器狗上一次合法动作的位置。
 100| 一次合法 /measure 或 /clear 的移动耗时为
 101| 移动耗时=两次位置之间的直线距离移动速度
 102| 默认移动速度：5 m/s
 103| 例如，从 (0,0) 移动到 (300,400)，直线距离为 500 米，移动耗时为
 104| 5005=100 (秒)
 105| 4.3. 检测耗时
 106| 一次合法 /measure 的总耗时为
 107| 检测总耗时=移动耗时+切换频道耗时+检测动作耗时
 108| 默认值：
 109| 检测动作耗时：5 秒。
 110| 切换频道耗时：1 秒。
 111| 切换频道耗时只看合法 /measure：
 112| 如果本次合法 /measure 的 channel 与测向机当前频道不同，切换频道耗时为 1 秒。
 113| 如果频道相同，切换频道耗时为 0 秒。
 114| 合法 /measure 完成后，测向机当前频道会更新为本次检测频道。
 115| 4.4. 清除耗时
 116| 一次合法 /clear 的总耗时为
 117| 清除总耗时=移动耗时+清除动作耗时
 118| 默认值：
 119| 未发现可清除目标时，只有精确定位动作，没有清除动作，耗时为 3 秒。
 120| 成功清除时，精确定位与清除两个动作总耗时为 5 秒。
 121| /clear 不产生切换频道耗时，也不会改变测向机当前频道。
 122| 4.5. 现实时间和虚拟时间
 123| 用户在模拟器中确认开始后，模拟器先准备数据。数据准备完成后显示5秒倒计时。倒计时结束时开启25分钟测试窗口并开放机器狗接口。
 124| 机器狗成功调用 /enter 后开始计算最长20分钟的程序运行时间。实际现实截止时刻是“25分钟窗口截止”和“/enter 成功后20分钟”两者中较早的时刻。/enter 成功响应中的 remaining_real_duration_s 是本局实际还能使用的完整现实时间秒数，范围为0至1200；机器狗程序应使用该值，不应固定假定每次都有1200秒。
 125| 虚拟世界限时为360000秒。达到现实时间或虚拟时间截止条件后，模拟器结束测试并关闭机器狗接口。截止前已经完整到达并被登记的唯一动作允许完成；在截止时刻或之后才完整到达的请求不再执行，连接可能直接关闭。测试结束后不能再调用 /exit 查询原因，具体结束原因由模拟器界面显示。
 126| 5. 通信格式总规则
 127| 5.1. 请求格式
 128| 4条指令都使用 HTTP+JSON。
 129| 方法：POST
 130| 请求头：Content-Type 必须是 application/json，可以带且只允许参数 charset=utf-8。出现其他参数时返回 HTTP 415。
 131| Content-Encoding 可以省略，或为 identity。其他值返回 HTTP 415。
 132| 请求体必须是无 BOM 的 UTF-8 JSON 对象，不能有重复键；JSON 嵌套不超过16层；请求体最大65536字节。
 133| 路径必须精确为 /enter、/measure、/clear 或 /exit，不接受尾随斜线和查询参数。
 134| 请求体必须是UTF-8 JSON对象，不能有重复键；请求体最大65536字节。
 135| channel 必须是 1 至 20 的整数。写成 JSON number 1.0 且数值恰好为整数时也会被接受；如写成1.5 则返回 HTTP 400。
 136| 未声明的JSON字段不会被忽略，而是返回HTTP 200和 accepted=false，用于帮助发现字段拼写错误。
 137| arena_id 必须是ASCII字符串“default”。
 138| robot_id 必须逐字节等于当前登录参赛队号，UTF-8长度为1至64字节。
 139| request_id 是当前测试会话内的幂等键，UTF-8长度为1至128字节。robot_id 和 request_id 不能包含控制字符或不可见格式字符。
 140| 5.2. 响应格式
 141| 业务响应也是 JSON 对象。
 142| 所有 JSON 业务响应都有以下字段：
 143| 字段
 144| 类型
 145| 含义
 146| accepted
 147| boolean
 148| 模拟器是否接受本次请求。
 149| real_timestamp_ms
 150| number
 151| 模拟器响应时的现实世界时间戳，单位为毫秒。
 152| virtual_time_s
 153| number
 154| 虚拟时钟，单位为秒。
 155| 如果 accepted=false，响应只包含上面 3 个字段，不包含检测结果、清除结果或退出原因。
 156| 5.3. HTTP状态和业务接受状态
 157| HTTP状态
 158| 含义
 159| 200，accepted=true
 160| 动作已执行。
 161| 200，accepted=false
 162| JSON结构合法，但当前测试状态拒绝动作；或存在未知字段；或 arena_id、robot_id 不匹配。
 163| 400
 164| JSON语法、重复键、缺失字段、字段类型、标识符格式、频道或坐标范围错误。
 165| 404
 166| 路径未知或路径不精确。
 167| 405
 168| 已知路径使用了非POST方法。
 169| 409
 170| 同一 request_id 对应了不同动作，或并发发送了不同动作。
 171| 413
 172| 请求体超过65536字节。
 173| 415
 174| Content-Type 或 Content-Encoding 不受支持。
 175| 429
 176| 连接/无效流量保护触发，或本局幂等记录达到上限。
 177| 500
 178| 模拟器内部错误。
 179| 所有能够形成HTTP响应的错误都返回JSON，其中至少包含 accepted、real_timestamp_ms 和 virtual_time_s。机器狗程序必须同时检查HTTP状态和 accepted，不能只判断其中一个。
 180| 每个新动作必须使用新的 request_id。只有在网络超时、连接中断等情况下重试完全相同的动作时，才复用原请求内容和原 request_id。同一ID、同一内容返回第一次的完整响应，不重复移动、检测、清除、退出或推进时间；同一ID改动路径、位置、频道等内容返回HTTP 409。结构错误、未知字段以及 arena_id、robot_id 不匹配不占用该ID，修正请求后可以复用。正常串行合法动作不设速率上限，但不同新动作不得并发发送。
 181| 并非所有错误都能形成HTTP响应。倒计时未结束、接口尚未开放、测试已经结束，或模拟器内部无法继续服务时，连接可能被直接关闭，此时没有JSON体。机器狗程序必须同时处理“连不上”和“收到JSON”。
 182| 结构错误（HTTP 400）以及未知字段、arena_id / robot_id 不匹配（HTTP 200且 accepted=false）不占用该 request_id，修正后可以复用。业务上已被接受的动作占用该 request_id。

 297| 7.3. 三种检测结果
 298| 无信号：
 299| {  "accepted": true,  "real_timestamp_ms": 1760000000000,  "virtual_time_s": 105,  "measure_result": "no_signal"}
 300| 含义：当前位置接收不到该频道的干扰源信号。可能原因包括该频道没有未清除干扰源、距离超过最大可被有效接收距离、定向干扰源没有覆盖该位置等。
 301| 距离过近：
 302| {  "accepted": true,  "real_timestamp_ms": 1760000000000,  "virtual_time_s": 105,  "measure_result": "near"}
 303| 含义：已检测到该频道信号，但距离干扰源不超过 5 米。此时不返回 svd_deg。
 304| 正常返回示向度：
 305| {  "accepted": true,  "real_timestamp_ms": 1760000000000,  "virtual_time_s": 105,  "measure_result": "direction",  "svd_deg": 123.45}
 306| 含义：已检测到该频道信号，并返回从检测点指向干扰源的方位角。svd_deg 保留两位小数，包含误差，参见题目正文。
 307| 7.4. 请求未执行的常见原因
 308| HTTP 200且 accepted=false：
 309| 尚未成功调用 /enter。
 310| arena_id 不是 "default"。
 311| robot_id 与当前登录参赛队号不一致。
 312| 请求包含未声明字段，包括 position 下的未知字段。
 313| 机器狗已经退出，或测试已经因超时等原因结束。
 314| HTTP 400：
 315| 请求体不是合法 JSON，或含有重复键。
 316| 缺少 position、position.x、position.y 或 channel。
 317| position.x 或 position.y 不是有限数值（含 NaN、正负无穷大），或绝对值超过2000000。
 318| channel 不在 1..20 范围内，或不是整数。
 319| robot_id 或 request_id 格式不合法。

 327| 取值说明

 329| string
 330| 是
 331| 必须是 "default"。
 332| robot_id
 333| string
 334| 是

 336| request_id
 337| string
 338| 是

 341| object
 342| 是

 349| number

 358| 8.2. 清除规则
 359| 清除半径是 20 米。
 360| 如果指定频道的未清除干扰源距离 position 小于等于 20 米，则清除成功。注意，无论全向还是定向干扰源，只要指定频道的干扰源距离小于等于 20 米，都能够精确定位并清除，不受定向干扰源有效覆盖角度范围的限制。
 361| 如果该频道不存在干扰源、干扰源已经被清除、或干扰源距离超过 20 米，都视为未发现可清除目标。
 362| 同一个干扰源只能清除一次。重复清除已被清除的干扰源，会返回未发现可清除目标。
 363| /clear 不会切换测向机当前频道。

 366| 字段
 367| 类型

 370| boolean
 371| true。

 373| number

 375| virtual_time_s
 376| number
 377| 本次清除完成后的虚拟时刻。
 378| clear_result
 379| string

 381| 8.4. 两种清除结果

 535| 12. 编程注意事项
 536| 先在模拟器中在线登录，启动测试，等待界面显示机器狗接口已经就绪。
 537| 使用当前登录参赛队号作为 robot_id。
 538| 每个新动作使用新的 request_id；只在重试完全相同动作时复用原ID和原请求内容。
 539| 逐次等待响应，不得并发发送不同动作；正常串行合法动作没有速率上限。
 540| 同时检查HTTP状态和 accepted。accepted=false 时动作没有生效，virtual_time_s=0 不是当前虚拟时刻。
 541| 使用 /enter 返回的 remaining_real_duration_s 控制现实运行时间，不要固定假定有1200秒。
 542| 每次检测增加的5秒是虚拟耗时，现实中不需要等待5秒。
 543| 只有 measure_result="direction" 时才读取 svd_deg，并且不是精确的真实方位，有误差。
 544| /clear 不切换测向机频道；只有成功的 /measure 可能会更新当前频道。
 545| no_signal 不等于附近一定没有干扰源；也可能是超出接收距离或不在定向覆盖范围内。
 546| 测试超时、中止或其他原因结束测试后接口会关闭；不要尝试调用 /exit 查询原因。
 547| 程序判断JSON取值时使用 direction、near、no_signal、success、no_target_in_range 和 user_exit 等实际字符串，不依赖界面中文说明。
 548| 机器狗程序应该自行记录测试过程中的指令序列、响应信息等内容，模拟器没有这一功能。
 549| 倒计时未结束、测试已经结束或接口未开放时，连接可能直接失败，没有JSON体。
 550| 加密日志文件上传上限为2MB，与机器狗接口协议无关；机器狗程序应避免异常高频循环。
